# Aurora 笔记网站设计规格

日期：2026-10-07  
状态：已由用户确认，可进入实施规划

## 1. 产品目标

Aurora 是一个首先服务读者的中文个人学习笔记网站。读者应能：

1. 按分类快速找到课程或专题；
2. 在课程/专题内理解知识结构并进入目标章节；
3. 在正文中通过章节树、页内目录和内部链接快速定位；
4. 获得稳定、清晰、无账号和无广告干扰的阅读体验。

网站不是 Obsidian 编辑器的替代品。Obsidian Vault 是唯一内容源，Aurora 仓库仅保存被明确发布的公开副本、网页代码及生成产物所需配置。

## 2. 职责边界

### Obsidian 维护 skill

- 创建、修改、组织源笔记；
- 维护 `40 Published`；
- 只有用户明确要求发布时才移动笔记；
- 发布前发现内容问题必须暂停并汇报，用户确认后才继续；
- 管理发布、撤回以及源文件路径变化。

### Aurora 网站维护 skill

- 对 Vault 只读；
- 从 `40 Published` 同步可发布内容；
- 转换 Markdown、链接和附件；
- 校验公开安全性、结构、构建与链接；
- 生成预览、变更报告，并按授权策略部署；
- 不修改源笔记，不决定某篇笔记是否应发布。

## 3. 信息架构

主层级为：

`分类 → 课程/专题 → 章节/笔记`

- 课程与专题均由现有 `type: course-moc` MOC 充当入口，不强制 `_index.md`。
- 复习笔记归入对应课程/专题，并在“复习与总结”区域呈现。
- URL 使用稳定 `slug`，不依赖 Vault 物理路径。
- 默认笔记 URL：`/aurora/notes/{slug}/`。

### 首页

- 顶部透明玻璃导航；
- 励志名言主视觉；
- 搜索入口；
- 真实感、慢速自转的天体：深色主题使用地球，浅色主题使用月球；
- 分类、精选课程/专题、最近更新；
- 所有卡片与搜索框使用一致的透明玻璃语言，可清楚看到背景星际与银河。

### 课程/专题页

包含简介、先修知识、学习路线或专题关系、章节列表、章节摘要、复习与总结、最近更新。不显示阅读进度、适合人群或预计学习范围。

### 笔记阅读页

- 桌面端：左侧章节树、中间正文、右侧当前笔记目录；
- 移动端：两侧导航折叠为抽屉；
- 正文保持安静、窄行宽和高对比度；
- 目录支持快速定位当前章节；
- 不显示反向链接，不嵌入 PDF 阅读器。

## 4. 视觉系统

核心风格为“空灵、克制、夜空感的玻璃拟态”，不是高不透明度的蓝色卡片。

深色主题：黑色银河星空、冷蓝边缘光、香槟金点缀、地球。  
浅色主题：明亮天空/宇宙薄雾、冷灰蓝玻璃、柔和金色点缀、月球；必须独立设计，不是颜色反转。

玻璃基线：

- 填充：白色约 14%；
- 描边：白色约 17%，1px 内描边；
- 背景模糊：20px；
- 阴影：`0 2px 20px rgba(0, 0, 0, .5)`，浅色主题单独调校；
- 所有导航、搜索、分类卡、课程卡使用同一 token 系统；
- 提供 `prefers-reduced-motion` 降级。

Three.js 只用于首页天体。阅读页不加载 WebGL。低性能、无 WebGL 或减少动态偏好环境使用静态图降级。

## 5. 内容合同

源 Vault：`D:\Obsidian\files\Learning-Notes`  
发布目录：`40 Published\Courses`、`40 Published\Reviews`、`40 Published\Tools`  
附件目录：`90 Attachments`

网站所需公开字段：

- `title`
- `type`
- `slug`（稳定且全局唯一）
- `category`（稳定分类 ID）
- `summary`
- `status`
- `created`
- `updated`
- `course` / `parent` / `chapter`（按类型使用）
- `tags`（可选）

只有 `status: complete` 或 `status: evergreen` 默认可发布。分类 ID 必须存在于仓库内的分类注册表。

下列字段不得进入公开仓库或网页：

- `source_user`
- `source_web`
- `source-index`
- 未加入公开白名单的 frontmatter
- 本地绝对路径

## 6. 内容转换能力

支持 Markdown、表格、脚注、Obsidian wiki 链接与锚点、图片、callout、代码块、LaTeX、Mermaid、笔记章节嵌入和受限原始 HTML。

- 未发布目标链接：硬阻断部署；
- 缺失/歧义/损坏附件：硬阻断；
- 仅复制被公开笔记实际引用的附件；
- 图片生成网页优化版本，原始图片的隐私与授权由用户负责；skill 不做 OCR、EXIF 或内容审核；
- 不覆盖全文搜索索引；搜索只索引标题、分类/课程/专题名、标题层级、摘要和标签。

HTML 禁止：`script`、`object`、`embed`、内联事件处理器、`javascript:` URL。`iframe` 只允许配置中的域名。

## 7. 隐私与安全

- 任何包含个人信息、敏感信息、密钥或本地路径的文字都不得公开；
- 对 frontmatter、正文、生成文件和 Git diff 执行敏感文本扫描；
- 报告命中时只显示脱敏结果；
- 图片隐私由用户负责，工具只做引用解析和技术校验；
- 网站无账号、评论、统计、广告、Cookie 跟踪；
- 核心前端资源本地托管。

## 8. 校验等级

### 硬阻断

Schema 错误、重复 slug、未知分类、父级缺失、链接指向未发布笔记、附件缺失、危险 HTML、敏感数据、路径逃逸、构建或测试失败。不得“一键忽略全部”；例外必须精确到单项。

### 警告

大图、缺失 alt、摘要异常、标题级别跳跃、过长页面、未知代码语言、复杂 Mermaid。存在警告时必须人工确认部署。

### 信息

正常增删改、生成结果和构建统计。

## 9. 部署与授权

- GitHub Actions 构建，GitHub Pages 部署；
- 生成的 `dist` 不提交；
- 每次部署使用一个原子 Git commit；
- 默认每次部署都需要用户确认；
- 同类低风险重复任务只有在用户明确授权该任务类别后才可自动部署；
- 删除/撤回、slug/URL 变化、分类结构移动、视觉/代码/依赖/工作流变化、警告或错误、大规模 diff、回滚永远需要单独确认；
- 依赖升级永远单独确认；
- 回滚必须人工确认并重新执行完整校验，不能绕过已撤回内容和当前安全策略。

## 10. 技术栈

- Astro：静态优先、适合内容网站、组件化且客户端 JavaScript 可控；
- Unified / remark / rehype：可测试的 Obsidian Markdown 转换管线；
- Pagefind：静态搜索，无需服务器；
- Three.js：仅首页真实感地球/月球；
- TypeScript：内容模型和同步逻辑；
- Sharp：图片优化；
- Vitest：转换与策略单元测试；
- Playwright：导航、主题、搜索和响应式端到端验证；
- GitHub Actions + Pages：低成本持续部署。

相对 Next.js，该方案不需要服务端运行时且页面负担更小；相对 MkDocs，视觉与内容转换扩展性更强；相对纯手写静态站，结构化内容、构建、搜索和长期维护成本更低。

未来风险包括：Astro/插件升级、Obsidian 语法边界、Three.js 性能、GitHub Actions/Pages 配额、内容规模导致构建变慢、搜索仅元数据带来的召回限制。应通过锁定依赖、Fixture 测试、静态降级、增量同步和显式升级流程控制。

## 11. 完成标准

首个可部署版本必须满足：

1. 首页、分类、课程/专题和笔记页均可用；
2. 深浅主题与天体降级正确；
3. 已批准的 Obsidian 语法可转换；
4. 搜索不索引正文；
5. 公开字段白名单和安全门生效；
6. 本地预览、单元测试、端到端测试和生产构建通过；
7. 部署前生成清晰、脱敏的人工确认报告；
8. 未经用户确认不推送或部署。
